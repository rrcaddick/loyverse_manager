Why: the owner judged both builds "the same grey with the barest hue change"
and could not see hover, elevation or a theme change. Measured, he was

## The system now in use (ladder D, chosen by the owner on the calibration sheet)

Tokens are generated by `frontend/scripts/gen-m3-tokens.mjs` from one seed per
theme with Google's Material colour utilities. Material's own light ladder
(white, 96, 94, 92, 90) was tried first and rejected: on a desktop monitor
two- to four-tone steps read as one surface. The owner picked the banded
ladder from `frontend/scripts/palette-calibration.mjs`: every region that is
seen at once sits ten or more tones from the others, and the navigation is
a dark column in light mode.

| App token | Light (tone) | Dark (tone) |
| --- | --- | --- |
| sidebar | neutral 22, text 92, filled active item on the primary | primary 23, text 94 |
| canvas (`--background`) | neutral 90 | neutral 8 |
| card | 100, outline-variant 70 border, level-1 shadow | 22, border 45 |
| zebra row, muted, nested | 94 | 27 |
| table head (`--surface-high`, menu hover) | 80, text on-surface-variant 30 | 32 |
| text / secondary / faint | 10 / 30 / 50 | 95 / 80 / 60 |
| primary (fills) | vivid palette on the seed hue, tone 35, white text | tone 44, white text |
| primary as text (`--primary-text`) | tone 35 | tone 80 |
| selected row, primary container | vivid 90 / 88 | vivid 32 / 30 |
| hover, focus | on-surface at 8 % / 12 % | same |

Graphite, the ink-and-paper default, keeps a near-black button in light and
a near-white one in dark instead of a forced hue. Semantic fills are deeper
than Material's tone-90 pastels: fill 82 with text 20 in light, fill 32 with
text 92 in dark; solids 38 / 42 with white text. The calendar heat ramp is
amber 92 → 57 (light) and 20 → 43 (dark), ink text throughout.

## Every colour from the seed (no hand-picked hues)

After the owner's objection to invented accent hues, the generator derives
everything from each theme's primary colour through Material's own scheme:

| App use | Material role |
| --- | --- |
| button, table head, active tab / chip / nav item | primary / on-primary |
| primary as text | primary (light) · primary tone 80 (dark) |
| selected row | inverse-primary (light) · primary-container (dark) with a primary edge bar |
| chips, neutral pill | secondary-container / on-secondary-container |
| count badges, dots (the accent) | tertiary / on-tertiary; on dark surfaces in light mode tertiary-container / on-tertiary-container |
| navigation column | inverse-surface + inverse-on-surface (light) · primary-container + on-primary-container (dark); active item inverse-primary (light) · primary (dark) |
| red (cancel, error) | error / on-error / error-container |
| green, amber, blue (meaning) | custom colours harmonised to the seed with Blend.harmonize, container tone 90 / 30, text tone 30 / 80 |
| heat ramp | the harmonised amber palette |
| borders, row rules | outline-variant / outline |

Scheme variants: Vibrant for the coloured themes (keeps chroma), Neutral for
Graphite, Monochrome at contrast 1.0 for High contrast. The surface ladder
(canvas 90 / 8, card 100 / 22, zebra 88 / 32, table head = primary) is the
owner's calibration choice drawn from the scheme's neutral palette; hover is
the primary at 50 % (light) / 28 % (dark) over the row, the owner's choice.

0.5), a theme change moves every surface, not only the button.

## Meaning of the two amber pills

Amber means "the move is ours". It lives on the **Last action** pill
(Customer reply, Payment received) and on an overdue deposit date. Booking
status pills therefore use the quiet tinted neutral for Pending, blue for a
new Request, green for Confirmed, red for Cancelled.

## Verified by

`frontend/scripts/check-palette.mjs` measures, per theme and mode, the
lightness gap between the surfaces seen together (canvas–card ≥ 0.08,
canvas–head ≥ 0.08, canvas–sidebar ≥ 0.10, card–zebra ≥ 0.035, card–hover
≥ 0.04, card–selected ≥ 0.05) and the contrast of every text role and pill,
and fails below the minimums. `check-contrast.mjs` still runs
for the WCAG text pairs.
