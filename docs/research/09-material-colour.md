# 09 · Colour on Material 3 roles

Why: the owner judged both builds "the same grey with the barest hue change"
and could not see hover, elevation or a theme change. Measured, he was
right: surfaces differed by 2–4 % lightness at near-zero chroma, hover was a
surface swap, shadows sat at 7 % opacity, and themes changed only the accent.

## The system now in use

Tokens are generated by `frontend/scripts/gen-m3-tokens.mjs` from one seed per
theme with Google's Material colour utilities (the same code Android uses for
dynamic colour). A seed yields six tonal palettes (primary, secondary,
tertiary, error, neutral, neutral-variant); the scheme picks tones per role
for light and dark. The app's token names are kept and mapped to roles:

| App token | Material role, light / dark |
| --- | --- |
| canvas (`--background`) | surface-container (tone 94) / surface (6) |
| card | surface-container-lowest (100) / surface-container (12), level-1 shadow, outline-variant border |
| nested, zebra rows, muted | surface-container-low (96) / surface-container-high (17) |
| table head, menu hover (`--surface-high`, `--accent`) | surface-container-high (92) / -highest (22) |
| sidebar | surface-container-highest (90) / surface-container-low (10) |
| popover | lowest + level-3 shadow / surface-container-highest |
| text | on-surface (10 / 90); secondary on-surface-variant (30 / 80); faint outline |
| borders | outline-variant (80 / 30); strong outline (50 / 60) |
| primary, primary-foreground, primary-soft | primary, on-primary, primary-container |
| selected row, active nav, "secondary" | secondary-container / on-secondary-container |
| hover, focus | state layers: on-surface at 8 % and 12 % (`--surface-hover`, `--state-focus`) |
| destructive | error / on-error |

Semantic hues are fixed tonal palettes in every theme, so a meaning is the
same colour everywhere: green 145, amber 72, red 25, blue 250 (text tone 30 /
80, soft fill 90 / 30, solid 40), grey from the theme's neutral-variant.
The calendar heat ramp is the amber palette, tones 95 → 60 (light) and
25 → 45 (dark), ink text throughout.

Elevation uses Material's levels: 1 for cards, 2 for raised controls, 3 for
popovers and dialogs (key light 30 % plus ambient 15 %).

Because surfaces now carry the seed's tint (neutral chroma 4–8 rather than
0.5), a theme change moves every surface, not only the button.

## Meaning of the two amber pills

Amber means "the move is ours". It lives on the **Last action** pill
(Customer reply, Payment received) and on an overdue deposit date. Booking
status pills therefore use the quiet tinted neutral for Pending, blue for a
new Request, green for Confirmed, red for Cancelled.

## Verified by

`frontend/scripts/check-palette.mjs` measures, per theme and mode, the
lightness gap between adjacent surfaces (canvas–card, card–zebra,
zebra–header, canvas–sidebar, card–hover) and the contrast of every text
role and pill, and fails below the minimums. `check-contrast.mjs` still runs
for the WCAG text pairs.
